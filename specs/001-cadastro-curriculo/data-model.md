# Phase 1 Data Model: Cadastro de Currículo

**Feature**: 001-cadastro-curriculo
**Date**: 2026-08-15

Derived from the Key Entities and Functional Requirements in [spec.md](./spec.md).

## Entity: Registration (`registrations`)

One row per candidate submission. Stored in Supabase Postgres.

| Column | Type | Nullable | Description | Source requirement |
|--------|------|----------|-------------|--------------------|
| `id` | `uuid` PK, default `gen_random_uuid()` | no | Record identifier, returned to the client on success | — |
| `full_name` | `text` | no | Candidate's full name, 1–100 chars after trimming | FR-006, FR-008 |
| `birth_date` | `date` | no | Date of birth; must not be in the future | FR-009 |
| `email` | `text` | no | Contact email, valid format | FR-010 |
| `phone` | `text` | no | Contact phone, stored as **digits only** (10 or 11 chars) | FR-011 |
| `city` | `text` | no | Residence city name, free text, 1–100 chars after trimming | FR-012 |
| `state_uf` | `text` | no | Residence state, exactly 2 uppercase chars, one of the 27 UFs | FR-012a, FR-012b |
| `desired_roles` | `text[]` | no | One or more values from the `job_roles` set; array must be non-empty | FR-013, FR-014 |
| `cv_file_name` | `text` | no | Original uploaded file name | FR-002 |
| `cv_file_size` | `integer` | no | File size in bytes, 1–4194304 | FR-004 |
| `cv_content_type` | `text` | no | MIME type; one of the accepted Word/PDF types | FR-003 |
| `cv_storage_path` | `text` | no | Path within the `curriculos` bucket, e.g. `<uuid>/<sanitised-name>` | FR-017 |
| `created_at` | `timestamptz` | no | Submission timestamp, default `now()` | Key Entities |

**Indexes**: primary key on `id` only. No further indexes — the prototype has
no listing or search requirement (see plan.md "Out of Scope").

**Row Level Security**: enabled with **no public policies**. All access is via
the backend using the service role key, which bypasses RLS. The browser never
talks to Postgres directly.

## Value Set: Job Roles (`job_roles`)

The nine fixed options rendered as checkboxes (FR-013). Stored as an array of
these exact string values in `desired_roles`, validated against this list on
both frontend and backend.

| Stored value | Label shown to the candidate |
|--------------|------------------------------|
| `pedreiro` | Pedreiro |
| `ajudante_pedreiro` | Ajudante de pedreiro |
| `eletricista` | Eletricista |
| `motorista` | Motorista |
| `cozinheiro` | Cozinheiro |
| `marceneiro` | Marceneiro |
| `tecnico_seguranca_trabalho` | Técnico em segurança do trabalho |
| `porteiro` | Porteiro |
| `outros` | Outros |

Stored as slugs rather than display labels so the UI wording can change without
a data migration. Enforced by a Postgres `CHECK` constraint that every array
element is a member of this set, plus `array_length(desired_roles, 1) >= 1`.

## Value Set: Brazilian States (`state_uf`)

The 27 federative units (26 states + the Federal District) offered in the "UF"
dropdown (FR-012a). Exactly one is selected per registration. Stored and
displayed as the two-letter uppercase code.

| Code | State | Code | State | Code | State |
|------|-------|------|-------|------|-------|
| `AC` | Acre | `MA` | Maranhão | `RJ` | Rio de Janeiro |
| `AL` | Alagoas | `MT` | Mato Grosso | `RN` | Rio Grande do Norte |
| `AP` | Amapá | `MS` | Mato Grosso do Sul | `RS` | Rio Grande do Sul |
| `AM` | Amazonas | `MG` | Minas Gerais | `RO` | Rondônia |
| `BA` | Bahia | `PA` | Pará | `RR` | Roraima |
| `CE` | Ceará | `PB` | Paraíba | `SC` | Santa Catarina |
| `DF` | Distrito Federal | `PR` | Paraná | `SP` | São Paulo |
| `ES` | Espírito Santo | `PE` | Pernambuco | `SE` | Sergipe |
| `GO` | Goiás | `PI` | Piauí | `TO` | Tocantins |

The dropdown shows only the code (e.g. `RJ`), per spec Assumptions; the state
names above are reference only and are not stored. The list is ordered
alphabetically by code in the UI. Enforced by a Postgres `CHECK` constraint
against this exact set, and by an Angular `Validators.required` on a
`mat-select` whose options come from the same constant.

**City/UF consistency is not validated** — a candidate may pair any city name
with any UF (see spec Assumptions). No municipality database is consulted.

## Stored File: CV Attachment

Held in the Supabase Storage private bucket `curriculos`, **not** in Postgres.

| Property | Rule | Source requirement |
|----------|------|--------------------|
| Path | `<generated uuid>/<sanitised original filename>` — the uuid is generated by the backend before upload and reused as the row's `id` | — |
| Count | Exactly one file per registration; a re-attach in the UI replaces the pending selection before submit | FR-005 |
| Max size | 4 MB (4194304 bytes) | FR-004 |
| Accepted types | `application/pdf`, `application/msword` (.doc), `application/vnd.openxmlformats-officedocument.wordprocessingml.document` (.docx) | FR-003 |
| Accepted extensions | `.pdf`, `.doc`, `.docx` — checked in addition to MIME type, since browsers report `.doc` MIME inconsistently | FR-003 |
| Visibility | Private bucket; written only by the backend using the service role key | research.md §R6 |

## Validation Rules

Applied on the **frontend** for immediate feedback and re-applied on the
**backend** as the authoritative check (backend rejection is what guarantees
FR-016 and data integrity).

| Field | Rule | Failure behaviour |
|-------|------|-------------------|
| `full_name` | Required; trimmed length 1–100 | Blocks submit; dialog "Preencha todos os campos" (FR-016) |
| `birth_date` | Required; a valid calendar date; **not after today** | Same; datepicker `max` set to today (FR-009) |
| `email` | Required; matches standard email format | Same (FR-010) |
| `phone` | Required; after stripping non-digits, 10 or 11 digits; if 11 digits the 3rd digit must be `9` | Same (FR-011) |
| `city` | Required; trimmed length 1–100 | Same (FR-012) |
| `state_uf` | Required; exactly one value from the 27-item UF set below | Same (FR-012a, FR-012b) |
| `desired_roles` | Required; at least 1 element; every element in the `job_roles` set | Same (FR-014) |
| CV file | Required; extension and MIME in the accepted set; size 1 byte–4 MB; exactly one | Rejected at selection time with an inline/dialog message naming the reason (format vs. size); missing file blocks submit with "Preencha todos os campos" (FR-002–FR-005, FR-016) |

Note the deliberate distinction: **file format/size problems are reported at
selection time with their specific reason** (spec Edge Cases), whereas any
missing-or-invalid field at submit time produces the single generic dialog
"Preencha todos os campos" required by FR-016.

## Record Lifecycle

A registration is created by a single request, so there are no intermediate
states and therefore no `status` column.

```text
   POST /api/registrations  (multipart: metadata + CV file)
                    │
                    ├─▶ validate every field ──── invalid ──▶ 400, nothing written
                    │                                          "Preencha todos os campos"
                    ├─▶ upload file to Storage ── fails ───▶ 500, nothing written
                    │
                    └─▶ insert row ───────────── fails ───▶ delete the uploaded
                                    │                        file, then 500
                                    ▼
                                  201 Created
                        → dialog "Salvo com sucesso",
                          form reset (FR-017)
```

- The file is uploaded before the row is inserted, and a failed insert deletes
  the file it just wrote, so storage and the table cannot drift apart.
- On any failure the candidate sees an error dialog and their typed values are
  **not** cleared (FR-019), so they can retry.
- Because both writes happen inside one request, a browser that dies mid-submit
  cannot strand a half-finished record — the failure modes above are the only
  ones.

## Schema DDL (reference)

Applied once via the Supabase SQL editor during setup — see
[quickstart.md](./quickstart.md).

```sql
create table if not exists registrations (
  id uuid primary key default gen_random_uuid(),
  full_name text not null check (char_length(trim(full_name)) between 1 and 100),
  birth_date date not null check (birth_date <= current_date),
  email text not null,
  phone text not null check (phone ~ '^[0-9]{10,11}$'),
  city text not null check (char_length(trim(city)) between 1 and 100),
  state_uf text not null check (state_uf in (
    'AC','AL','AP','AM','BA','CE','DF','ES','GO','MA','MT','MS','MG',
    'PA','PB','PR','PE','PI','RJ','RN','RS','RO','RR','SC','SP','SE','TO'
  )),
  desired_roles text[] not null check (
    array_length(desired_roles, 1) >= 1
    and desired_roles <@ array[
      'pedreiro','ajudante_pedreiro','eletricista','motorista','cozinheiro',
      'marceneiro','tecnico_seguranca_trabalho','porteiro','outros'
    ]::text[]
  ),
  cv_file_name text not null,
  cv_file_size integer not null check (cv_file_size > 0 and cv_file_size <= 4194304),
  cv_content_type text not null,
  cv_storage_path text not null,
  created_at timestamptz not null default now()
);

alter table registrations enable row level security;
-- No policies: only the service role key (backend) may read/write.
```
